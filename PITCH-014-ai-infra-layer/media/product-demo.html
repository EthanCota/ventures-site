Governframe — what using it looks like

Three scripted scenes: a team member's session connecting to the hosted layer, a knowledge-base query answered from the team's own docs, and the admin's isolation/audit view. Click through — nothing here calls a live system.

Illustrative example: a designer on a 9-person agency team opens Claude Code and points it at the team's Governframe MCP endpoint using their own existing subscription. No account or credential is shared with Governframe — the session is theirs.

connect mcp://agencyname.governframe.app --as jordan

Illustrative example: the roster is curated per role by the team's own admin — Jordan sees the tools relevant to design work, not the full catalog. This is the "don't want everyone using it willy-nilly" framing the offer is built around.

Scene 2 — a KB query answered from the team's own data

Illustrative example: Jordan asks a question that used to mean pinging a teammate or searching six old Slack threads.

what's our current file-naming convention for client deliverables, and did we change it after the Meridian project?
